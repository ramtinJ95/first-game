# Natural sea shores and readable small-settlement names

Baseline: main `24630b8d14926a302800b50b25491d56630ee83c`. All comparisons use the same seed-1 opening game and camera positions. No rule, city coordinate, map data, save format, dependency or outside art changes.

## Coast geometry

`node scripts/coast-metrics.ts` regenerates [the complete metrics](coast-metrics.json). A straight run means a **continuous** sequence within 20 m of one chord, not merely a subdivided source edge. The chosen maximum is 3.5 km (14 px at 4 px/km); the existing lake maximum remains 3 km.

| Measure                                                   |        Before |       After |
| --------------------------------------------------------- | ------------: | ----------: |
| Longest continuous straight sea-coast run                 | 108.096623 km | 3.172440 km |
| Longest run after actual closest-zoom line simplification | 108.096623 km | 3.172440 km |
| Maximum displacement from corresponding source coast edge |             0 | 0.436673 km |
| Geographic coast control points retained                  |         5,638 |       5,638 |

The selected deviation ceiling is **0.6 km**. All 131 coastline paths derive from one detailed land outline, shared by paper, ground/wash masks, water lines and coast ink. Every original anchor remains in order; only intermediate drawing points change. Fixed map-frame edges are unchanged. Seeded, bidirectional detail scales with quarter-clearance near islands and straits rather than clipping wave crests into long parallel lines. It is built lazily at close zoom, not charged to game start.

This is deliberately **art over an unchanged physical coast**: the original navigation geometry, ports, province outlines and picking remain authoritative. A coast can visually differ from the physical edge by at most the bound above.

`src/render/shore.test.ts` proves:

- all coast anchors in order, every sample within 0.6 km, and the 3.5 km continuous-run ceiling both before and after actual closest-zoom line simplification;
- no detailed ring crossings and unchanged island containment, and every non-coast frame edge retained;
- calling `naturalCoast` leaves the entire serialized map byte-identical; rebuilt navigation meshes and harbours deep-equal, with identical `provinceAt` results at sampled coast anchors and offsets on both sides;
- the five existing lake checks still hold. An additional one-off comparison against the pinned baseline found all 29 lake rings' generated JSON exactly equal, including island rings.

## Names and contrast

[Complete contrast table](village-contrast.md), regenerated by `node scripts/village-contrast.ts`, includes every exported ground/relief colour, sand, forest, paper, sea, all crop fills and each close owner wash. Village ink changes from `#675640` to `#3b2816`; both town and village names gain weight 600. Their existing opaque `#f4ead0`, 3 px halo remains. Solid-core contrast against that immediate backing rises **5.88 → 11.68:1**, exceeding the chosen **7:1 floor on every underlying ground**. Bare-ink/ground ratios are also reported honestly: dark ink cannot by itself contrast against dark tree ink. Anti-aliasing and the entrance fade are not solid glyph cores.

Villages remain 10 px italic and towns 11 px italic, below 12/14 px upright city/capital names. Italy's requested farmland view contains named towns, not villages; both small-settlement ranks use the stronger style so it improves too. City styles and coordinates, label priorities, placement algorithm and fades stay unchanged. Bolder widths can alter which nearby name fits.

## Rendering cost and verification

The first uncached detailed-coast trial exposed a real regression: 271.6 ms drawn-frame median at closest zoom versus a 35.2 ms baseline. Submitting the whole 192,457-point coast each frame was unacceptable. The final implementation caches static river/coast ink as one view texture with a 256 px margin, retaining the art's original stroke transform and layer order. Covered pans/resizes reuse it; zooms and uncovered views redraw it. Context restoration explicitly invalidates ink and schedules a paced redraw, with listener cleanup on destruction. The new cache unit checks cover reuse, pan/zoom/resize invalidation, transforms, resource destruction and restoration.

Measurements use production FULL drawing, Chromium SwiftShader, 1280×720, not the half-resolution test drawing. Ten fresh browser contexts per build measure navigation to the visible game HUD, matching the previous startup boundary. Closest frame measurements use three rounds at six views, the built-in synchronized GPU readback path, 1.5 s warmup and 5 s sampling. `--days 0` uses the same opening game at speed 1 for both builds, isolating rendering rather than load-save timing; no benchmark timeout or protocol was relaxed.

Measurements are local software-browser results, not a claim about a physical GPU or deployed preview. The local `nexus output` integration is unavailable; GitHub-published media is the evidence channel instead.
