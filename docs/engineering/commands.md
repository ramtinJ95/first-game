## Commands

| Command                                       | Does                                                                                                                                                        |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `npm run dev`                                 | Vite dev server                                                                                                                                             |
| `npm run build`                               | Production build to `dist/`                                                                                                                                 |
| `npm run check`                               | svelte-check, the sim type check, ESLint, Prettier                                                                                                          |
| `npm test`                                    | Vitest unit tests                                                                                                                                           |
| `npm run e2e`                                 | Playwright tests against the built page, Chromium only                                                                                                      |
| `npm run sim:battles [-- --log <row> <seed>]` | Play the battle matchups over many seeds and print the tuning table, or one battle day by day                                                               |
| `npm run sim:economy`                         | Play the new game for three years without orders and print each great power's economy at the end of each year                                               |
| `npm run sim:paths`                           | Compare grid and navigation-mesh path finding with the exact shortest path                                                                                  |
| `npm run sim:movement`                        | Print long routes, their marching days and path times, and the tick time with every army marching                                                           |
| `npm run map:routes`                          | Draw long routes on the map preview into `captures/movement/`                                                                                               |
| `npm run sim:sieges`                          | Play the siege, storm, relief, and fate cases and print the tuning table                                                                                    |
| `npm run sim:ai [-- --seeds <n> --years <n>]` | Play the new game under the AI, with every faction and with a passive Rome, and print the tuning tables, battle lengths, and beaten armies alive 30 days on |
| `npm run sim:opening`                         | Play the scripted opening of each great power against its nearest minor city on 5 seeds                                                                     |
| `npm run sim:world`                           | Play the new game for ten years under the AI and print who leads, who lives, and how often the AI repeats a siege                                           |
| `npm run sim:recruit`                         | Have Rome raise every troop it can afford and count what it waits for                                                                                       |
| `npm run sim:buildings`                       | Print the building table, each building's payback by city, and four Romes at peace that idle, recruit, build, or both                                       |
| `npm run sim:peace`                           | Play the new game under the AI and print how wars end, how long they run, and the days each power spends at peace                                           |
| `npm run sim:news [-- --seeds 5 --years 3]`   | Play the new game as Rome, idle and under the AI, and count the lines of news a year in the corner and in the chronicle                                     |
| `npm run capture [-- <scenario>]`             | Build, then write screenshots, `clip.gif`, video, and trace to `captures/<scenario>/`                                                                       |
| `npm run capture:publish`                     | Replace this branch's folder on `pr-assets` with its changed, new, and named scenarios, write its `README.md`, and print Markdown for the pull request      |
| `npm run capture:fetch`                       | Pull this branch's published folder from `pr-assets` into `captures/`, declare its images as Nexus outputs, and print the Markdown                          |

To show a new view, add a scenario file to `scripts/capture/scenarios/`. It default-exports `defineScenario({ name, title, run })`. `run` gets the Playwright `page` and `shot(name, title)`. The whole run becomes the clip.

CI runs `npm run capture` on every pull request and publishes to `pr-assets` only what a reviewer needs. It compares each screenshot with the same screenshot from the CI run of the base commit on `main`, or from the newest `main` run that still has its screenshots. It publishes the changed screenshots with the scenario's `clip.gif`, every image of a scenario that `main` lacks, and every image of each scenario you name. Unchanged screenshots stay out. Without a `main` run to compare with, every scenario is new. Locally, `capture:publish` compares with nothing unless you pass `--reference <dir>`, takes names with `--scenario <name>`, and reads open pull requests from the GitHub API with `GH_TOKEN`.

To publish a whole scenario, add a line to the pull request description, such as `Publish scenarios: map, fog`, or `Publish scenarios: all`. The names are scenario names, the folder names under `captures/`, separated by commas or spaces. An unknown name fails the publish and lists the known ones. CI reads the description when `publish-media` runs, so after you edit it, re-run that job.

`pr-assets` holds one commit and no history. Each publish replaces it with a commit that holds the folders of open pull requests, the newest `playtest/stage-<n>/` folder, and the publishing branch's folder rebuilt from its captures. A branch without an open pull request loses its folder at the next publish. The folder's `README.md` names the head commit the images show, the `main` run they were compared with, the published images by scenario, and the screenshots left out. Markdown links point at `refs/heads/pr-assets/<branch>/<scenario>/<file>`, never at a commit, so they show the newest publish and work while the pull request is open.

The run summary holds the same Markdown. The full set, with the video and the trace, stays in the run's artifacts (`captures-<n>` and `capture-recordings-<n>`) for the repository's artifact retention, beside the Playwright report. If your machine cannot install Chromium, push the branch, wait for CI, and run `npm run capture:fetch`.
