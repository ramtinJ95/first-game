# Working in this repository

Read `docs/design.md` before any work. It is the agreed design. When a task conflicts with it, stop and say so in the pull request.

## Layers

- `src/sim/` holds the game rules in pure TypeScript. It imports nothing from `src/render`, `src/ui`, `src/app`, `pixi.js`, or `svelte`, and it uses no DOM globals. `npm run check` enforces both rules through ESLint and `tsconfig.sim.json`.
- `src/render/` holds the PixiJS map renderer. It reads the state and never writes it.
- `src/ui/` holds the Svelte panels.
- `src/app/` wires the page together.
- `scripts/` holds build-time and tooling scripts. Node runs them as `.ts` files directly.
- Unit tests sit beside the code as `*.test.ts`. Playwright tests sit in `e2e/`.

## Rules code

- The game state is plain data that survives a round trip through JSON. It holds no classes and no functions.
- Ids are branded types.
- All randomness comes from the seeded generator in the state.
- The player and the AI change the state only through orders.
- Each system is one file under `src/sim/systems/`, with its tests beside it.

## The rules module

- `src/sim/state/` holds one file per kind of record. Each file defines a valibot schema and derives the type from it, so the schema is the one source of the shape and also the check that loading a save runs. `game-state.ts` gathers the collections. Each collection maps an id to its record.
- An army's `activity` is a tagged union (idle, marching, in battle, besieging, embarked). Add a variant instead of an optional field.
- Records that point at each other must agree: an army and its formations, a battle or a siege and its armies, a convoy and its armies, a province and its city. `findBrokenReferences` in `src/sim/references.ts` lists every disagreement. Loading rejects a save that has any. Every system test and every order test ends with `expectConsistent(state)`, which throws with that list. In development builds and in tests, the clock runs the same check after every tick and throws with the day. Production builds leave it out.
- New records get their ids from `allocateId` in `src/sim/ids.ts`, which counts in the state.
- Randomness comes from `nextRandom` and `nextInt` in `src/sim/rng.ts`, which advance `state.rng`. Never call `Math.random`.
- `buildFixture()` in `src/sim/fixture.ts` returns a fresh tiny valid state, and `FIXTURE` names its ids. Use it in tests.

### The tick contract

`tick(state, orders, world)` in `src/sim/tick.ts` plays one day. It never changes its input. It copies the state, applies the orders in the given order, then runs `SYSTEMS` in list order on the copy, and returns `{ state, rejected, events }`. Every order handler and every system receives the same `world`. Inside a tick, orders and systems change that copy in place. Outside the rules, a state is frozen once a tick returns it. The clock, the panels, and the renderer can keep and compare references to it without copying, and the renderer can draw between the previous and the current day.

### The day's events

`tick` also returns `events`, the `DayEvent`s of the day in the order they happened: a battle began or ended, an army retreated, was destroyed, or lost men to desertion, and a war was declared. `src/sim/events.ts` defines them. An event carries what a reader needs, such as owners, a position, and men, because the records it names may be gone by the end of the day.

- Rules code calls `emit(state, event)` where the change happens. The events are kept beside the tick's copy of the state, never in it, so they are not saved and a loaded game has none. `emit` outside a recorded day drops the event, so tests that call an order handler directly need nothing.
- A script that plays the tick's steps itself wraps them in `recordEvents(state, run)`, as `scripts/sim-ai.ts` does.
- A new kind of news is a new variant of `DayEvent`, emitted at the one place the change happens.

### The world

`buildWorld(map)` in `src/sim/world/world.ts` builds the `World` once from the parsed map: `{ map, mesh, harbours }`. It is never saved and never changes during play. The page builds it at start and hands it to the clock, and tests take `fixtureWorld()` from `src/sim/fixture.ts`, which is built from the committed `data/map/map.json`. A rule that needs geometry reads the world, never a copy of the map in the state.

- `mesh` is a constrained Delaunay triangulation of the map extent, with the coastline and the map edge as walls, on the map's 0.1 km lattice so it is the same on every machine. Each triangle is land, sea, or off the map. Triangles that reach each other across open edges share a `component`.
- `findPath(mesh, from, to, surface)` in `src/sim/world/find-path.ts` returns the waypoints of a short path on `'land'` or `'sea'`, or undefined. It keeps one set of working arrays per mesh between calls, so a search allocates no scratch. `surfaceAt` and `connected` answer cheaper questions.
- `harbours` maps each port city to the sea point nearest it, where convoys leave and land.

### Movement

- `src/sim/march.ts` names the speeds `MARCH_KM_PER_DAY`, `CONVOY_KM_PER_DAY`, and `REFUGEE_KM_PER_DAY`. `startMarch` is the one way to set an army marching: it finds the land path, or returns why there is none. No march takes longer than `MAX_MARCH_DAYS` (90), so a march round a sea is refused and the way by sea is the answer. `marchPath` gives the path with that check.
- A marching army, a convoy, and a refugee column hold the `waypoints` still ahead. The path is found once, when the march starts, and `src/sim/systems/movement.ts` follows it. Movement runs first in the day after `homecoming`.
- A retreating army walks its path like a marching one, but takes no order and fights no battle until it arrives and stands idle.
- `moveArmy` replaces any march, `halt` stops one, and `embark` puts an army aboard a convoy to another port. `embarkationAt` in `orders/embark.ts` says where it sails from: within `AT_PORT_KM` of its faction's port city or that city's harbour the ships are ready, and on any other shore within `SHORE_KM` of the sea, an enemy or neutral port included, the convoy waits `GATHER_DAYS` (`convoy.departsOn`) for its ships, so no army overseas is shut in. A besieging army may embark and leaves its siege. The order's `then` is where the army marches on once it lands. The land path is found when it embarks and kept on the embarked activity as `march`. Without `then`, an army bound for a port whose harbour lies farther than `SIEGE_DISTANCE` from the city marches into the city, so it stands at it and besieges an enemy's. Otherwise the convoy lands its armies idle at the destination harbour. `evacuate` gives a new refugee column its land path, and the column ends its walk at its destination with no waypoints, where `population` settles it.
- `npm run sim:paths` reruns the path-finding experiment, `npm run sim:movement` prints the route table and the tick times, and `npm run map:routes` draws routes on the map preview into `captures/movement/`.

### Adding a system

1. Write `src/sim/systems/<name>.ts`, which exports a `System`, `(state: GameState, world: World) => void`. A system that needs no geometry may leave out `world`. It changes the state it is given.
2. Add it to `SYSTEMS` in `src/sim/systems.ts`, at its place in the day: homecoming, movement, battles, sieges, economy, construction, population. `advanceDay` stays last.
3. Write `src/sim/systems/<name>.test.ts`, which starts from `buildFixture()` and ends each test with `expectConsistent(state)`.

The AI is not a system. It is a pure function from the state to a list of orders, and the clock adds those orders to the next tick.

A field that only your system needs goes into the kind's schema in `src/sim/state/`. A field that old saves lack needs a default with `v.optional(schema, default)`, or a raise of `SAVE_FORMAT` in `src/sim/save.ts`.

### Adding an order

1. Write `src/sim/orders/<name>.ts`. It exports the order's interface, with `kind` and `faction`, and a handler `(state, order, world) => string | undefined`. The handler checks everything before it writes anything. It returns a reason to reject, or `undefined` after it has applied the order. `ownedArmy` in `orders/owned-army.ts` does the ownership check.
2. Add the handler to `ORDER_HANDLERS` in `src/sim/orders/orders.ts`. The `Order` union derives from that table.

### New game

`newGame(map, { seed, player })` in `src/sim/new-game.ts` builds day 1 from the parsed map. The page fetches `data/map/map.json`, parses it with `parseMap`, and runs that state. `buildFixture()` stays the small state for unit tests.

- A province keeps the map's province id. Its city has the same id.
- A great power's faction id is its power id from the map, such as `rome`. Each independent city is its own minor faction, whose id is the city's province id. `kind` tells a `greatPower` from a `minor`.
- Armies and formations get their ids from `allocateId`.
- Starting populations and the starting army are the tables `STARTING_POPULATION` and `STARTING_FORMATIONS` in `new-game.ts`.
- Each minor is drawn from the seed as one of `MINOR_KINDS` in `new-game.ts` (a standing army, rich and walled, poor and open, leagued), with `FRONTIER_SHARES` instead of each kind's `share` beyond `FRONTIER_KM` of every great capital. A kind sets the city's population and `fortified`, the faction's stores, and its starting army. Leagued minors pair with the nearest unpaired leagued minor within `LEAGUE_KM` through `Faction.league`, which `findBrokenReferences` checks both ways. A minor declares war only to join a war on its partner, and marches to its partner's besieged city while its own is not besieged.

The map is static data outside the state. Outlines, neighbours, coastline, and rivers never go into the state. Rules code that needs geometry reads the `World`, which holds the map.

The map also holds terrain areas, peaks, and settlements. A settlement is a named place with no people and no rules. The rules that choose them sit at the top of `scripts/map/terrain.ts` and `scripts/map/settlements.ts`.

- A place is written by the name it bore in antiquity, read from Pleiades' own name records (`usualName` in `settlements.ts`): its title when one of its names in an ancient language, or dated in the game's periods and out of use by `MODERN_FROM`, has the same letters, or else the first such name, Latin before Greek. A place with no ancient name, such as one Pleiades knows only by a modern village or a "tepe", is not a candidate, so its room goes to a place with one. A test over the built map rejects any name with an editor's mark, accents, or a modern word such as "Tell" or "Col.".
- Natural Earth names the peaks in modern languages, so a peak's name is drawn only from `PEAK_NAMES` in `src/render/terrain/places.ts`, its classical name, and a peak not in it is drawn with none.

Known faults in the source data. Check them before you draw or label terrain.

- Natural Earth's English name for the whole Apennines is "Appennino Ligure", which is only their northern end.
- Natural Earth lists IJsselmeer, a modern polder lake, and Syvash, a lagoon of the Sea of Azov, as lakes. The build drops both by name.

### Battles

- `areAtWar(state, a, b)` in `src/sim/wars.ts` says whether two factions are at war. Every rule that asks uses it. `state.wars` maps `warKey(a, b)` to the war. The key is the JSON pair of the two faction ids in ascending order, so a pair is stored once and a faction is never at war with itself. Only orders such as `declareWar` change it.
- `TROOPS` in `src/sim/troops.ts` holds every number a battle uses for a troop: category, attack, defence, discipline, and bonuses against categories. `formation.troop` accepts only its keys.
- To add a troop type, add one row to `TROOPS` and nothing else. Add a matchup for it to `scripts/sim-battles.ts`, run `npm run sim:battles`, and put the table in the pull request. Renaming or removing a troop breaks old saves and needs a raise of `SAVE_FORMAT`.
- `src/sim/systems/battles.ts` names `ENGAGEMENT_DISTANCE`, the stance effects, and the tuning numbers at its top. `npm run sim:battles` prints the length of each matchup. Two armies of about the same strength fight 6 to 12 days, a side outnumbered two to one holds at least 3, and a formation loses at most `MAX_DAILY_LOSS` of its men a day or `REMNANT_MEN`, so only a remnant dies on its first day.
- `STANCE_BEATS` in `battles.ts` says which stance each stance beats, and `stanceEdge(mine, theirs)` gives what an army's stance multiplies its blows on another army by: `STANCE_EDGE`, 1, or its inverse. The beaten side's morale also falls `STANCE_EDGE` times as fast. A `setStance` that changes the stance sets `army.stanceChangedOn`, and for `REFORM_DAYS` the army re-forms (`reforming`): every enemy that is not re-forming meets it as the stance that beats it. `npm run sim:battles -- --stances` prints every stance against every stance, at even numbers, at 1.3 to 1, and for foot against horse and bows, and how often a side wins against the AI's stance rule under each line of play: holding, answering every day, answering once, and answering the AI's coming answer.
- `GENERAL_EFFECT` is what one point of general's skill adds to blows and morale, so the best general against none does not make up for a fifth more men. The AI's strength estimate reads the same constant. Every new army, at the start or raised by recruits, has a general of `STARTING_GENERAL_SKILL`.
- Every new army gets its name from `nameNewArmy(state, owner)` in `src/sim/army-names.ts` when it is raised, and keeps it for life. It counts the faction's `armiesRaised`. Rome numbers its legions ("First Legion"), Carthage names a host for a noble, Macedon a phalanx for a commander, Egypt a host for a god, Persia opens with the Immortals and then a satrapy, and a minor city raises "Army of <city>". The panels and alerts call an army by `armyTitle` in `src/app/names.ts`: the player's by its name, another power's as "Carthage's Host of Hanno".
- `retreatFromBattle(state, world, army, ordered)` is the one way out of a battle, so a lane that pulls an army out calls it. Every formation leaves at morale 0. Ordered out, each loses `RETREAT_LOSS` of its men. Beaten, each loses what the pursuit cuts down: `PURSUIT_BASE` plus `PURSUIT_PER_RIDER` for each unbroken enemy horseman per man of the army, up to `PURSUIT_MAX`.
- The army retreats to the nearest city of its owner that a land route of at most `MAX_RETREAT_DAYS` reaches, that is not besieged, that has no enemy army within `ENGAGEMENT_DISTANCE`, and that lies at least `SAFE_KM` from every army it fought. With no such city it goes `FIELD_RETREAT_KM` into the field, as directly away from those armies as the land allows. With neither it surrenders. `MAX_RETREAT_DAYS` is where walking to a city gets the army back to full morale later than falling back into the field and recovering there, 19 days, so a beaten army overseas falls back into the field and never walks round a sea. It is `retreating` until it arrives, so it fights no battle on the way. Once it stands idle, an enemy that marched after it can fight it again.
- When a battle ends, an army that holds the field takes up the march it was on when the battle took it (`inBattle.march`), so an order to march survives a battle on the way. An army that was idle or besieging stands where it fought.
- An army joins a battle when it stands within `ENGAGEMENT_DISTANCE` of the battle or of any army in it, and joining repeats until no army joins, so an enemy that one battle has taken cannot walk past an army at war with it.
- An army without an unbroken formation does not start or join a battle. Only idle armies regain morale: `MORALE_RECOVERY` a day in the field, and `REFUGE_RECOVERY` within `REFUGE_KM` of a city of their owner that no siege holds, so a beaten army that reached a safe city can face the enemy that follows it. `npm run sim:battles -- --chase` plays that chase.
- `removeArmy(state, army, cause)` in `src/sim/armies.ts` is the one way an army leaves the game, and it emits `armyDestroyed` with the cause.

### Peace

- A war remembers what it needs to be reckoned: `since`, `declaredBy`, and for each side in `sides` the other side's cities it took in the war and still holds (`taken`) and the men it lost in battle against the other (`lost`). `newWar(by, against, day)` in `src/sim/state/war.ts` makes one. `recordCapture` and `recordBattleLosses` in `src/sim/peace/war-record.ts` keep it, called from `changeCityOwner` and the battles system. A city won back is no longer the other side's gain.
- `warStanding(state, faction, enemy)` in `src/sim/peace/standing.ts` is the one place that says how a war stands for a side: the `CITY_POINTS` of the cities each side took and holds, `SIEGE_SHARE` of each city under siege, and up to `BATTLE_POINTS` for the men lost in battle, from facts the player can see.
- Terms (`PeaceTerms` in `src/sim/state/peace.ts`) are peace as things stand or a payment in which one side, the payer, gives gold, cities, or both. `termsPoints` in `src/sim/peace/terms.ts` prices them, `GOLD_PER_POINT` gold or a city's `CITY_POINTS` to a point. `termsProblem` refuses gold the payer lacks, a city it does not hold, and its last city, so a treaty never ends a faction and destroys no army.
- The orders are `offerPeace`, `acceptPeace`, and `refusePeace`. An offer waits in `state.peaceOffers`, one per war, for `OFFER_DAYS`, and replaces the other side's offer as a counter-offer, but not one made the same day. `makePeace` in `src/sim/peace/make-peace.ts` pays the terms, ends the war, and starts a truce in `state.truces` of `TRUCE_DAYS`. `declareWar` refuses during a truce, and the AI's war declarations, the coalition against a leader and a minor's league included, skip a faction it keeps a truce with (`truceBetween`).
- `homecoming` in `src/sim/systems/homecoming.ts` runs first in the day, after the orders, so no order given before the peace undoes it. On the peace's day it takes both sides' armies out of the battles they fight against each other and the sieges of each other's cities, and turns home every army and convoy of either side on the other's land or bound there (`sendHome` and `sailHome` in `src/sim/peace/home.ts`). On each day of the truce an idle army on the other's land goes on home, so one that marched to a shore takes ship. An army stands on the land of the owner of the city nearest it (`landOwnerAt`).
- The AI's rule is in `src/sim/ai/peace.ts`. `peaceWish` adds minus the standing, a point for each `WEARY_DAYS` of war up to `MAX_WEARINESS`, `OTHER_WAR_POINTS` for each other war with a great power, `SHORTAGE_POINTS` while gold or food is short, and minus `PEACE_RESOLVE`, with each reason in words. `peaceAnswer` accepts when the wish and the terms' worth reach 0, and the war is `MIN_WAR_DAYS` old. The panel shows the same answer. `proposal` finds terms both sides take, and `peaceOrders` answers the offers that wait and makes at most one offer a day, `OFFER_GAP_DAYS` after the last offer in that war. A great power and a minor both run it first in their day.
- `npm run sim:peace [-- --seeds 20 --years 10]` plays the new game under the AI and prints how wars end, how long they run, how soon a pair fights again, and the days each power spends at peace. `node scripts/peace-two-fronts.ts` plays the tester's case of Rome on two fronts in year 2.

### Cities

- Each faction holds `stores` of gold, food, and manpower. Gold and food go below zero when upkeep outruns them. While a store is below zero, each formation of the owner loses 1% of its men a day for each short store, and while food is short its cities shrink.
- Every man under arms costs gold and eats food each day (`UPKEEP_PER_MAN`). Every person of a city eats `FOOD_PER_PERSON`, in unrest or not, while unrest cuts what the city grows, so a freshly taken city costs food before it feeds its owner. A food deficit drains the store day by day before anyone deserts, so the player sees it coming in the balance.
- Food grows only up to `GRANARY_DAYS` of what the faction's people and men eat, and manpower only up to `MANPOWER_SHARE` of its people less its men under arms and in training, so a large army leaves few men to call up. `limitsOf(state)` gives both. A gain stops at the limit, and a store already above it, such as manpower from enslaving, is kept.
- Gold grows only up to `TREASURY_DAYS` of what the faction's people pay at full, in `limitsOf` like food and manpower. Past `ADMIN_CITIES` cities, each city of a realm yields `(ADMIN_CITIES / cities) ** ADMIN_EXPONENT` of its gold and manpower (`dailyBalances`), so a large realm's income grows ever more slowly.
- `economy` in `src/sim/systems/economy.ts` musters finished recruits, adds each city's output to its owner, and takes army upkeep. Its rates sit at its top. `dailyBalances(state)` gives each faction's income less upkeep for budgeting.
- `population` in `src/sim/systems/population.ts` grows or shrinks each city, counts unrest down, and settles each refugee column that stands at its destination.
- `changeCityOwner(state, city, owner)` in `src/sim/cities.ts` is the one way a city changes owner. It starts `UNREST_DAYS` of unrest and drops the recruits the old owner was raising there. A city in unrest produces less and cannot recruit.
- The cost and training days of each troop are its `recruit` row in `TROOPS`. A recruit costs as much manpower as it has men.
- A besieged city musters every recruit it trains at once, at full strength, into an idle army of its owner at the city, which then fights the besiegers. `musterEarly` in `economy.ts` does it, each day of a siege and before a storm. A besieged city starts no new training, so no recruit is ever lost with a city. `earlyMusters(before, after)` in `src/sim/cities.ts` lists the cities that mustered early between two days, for an alert.
- `npm run sim:economy [-- --years <n>]` plays the new game for three years, or `n`, without orders and prints each great power's stores and balance.

### Buildings

- `BUILDINGS` in `src/sim/buildings/buildings.ts` is the one table: each row's `name`, `gold`, `days`, `needs.people`, and its own effect fields. `BUILDING_KINDS` lists them: `forum`, `canals`, `barracks`, `towers`, `temple`. A city holds `buildings`, the kinds finished, and `construction`, the one at work with its `daysLeft`, or null. The rules, the AI, and the panel read the table, and every hook reads it through a function beside it: `goldShareOf` and `extraFoodOf` and `levyShareOf` in `dailyBalances` and `limitsOf`, `trainingDaysAt` in `recruit`, `defenceSharesOf` in `fullDefences`, and `unrestPaceOf` in `population`.
- The orders `build` and `cancelBuilding` live in `src/sim/buildings/build.ts`. `buildRefusal(state, city, building)` is the one check of whether a city can start a building now, which the order, the AI, and the panel share. The gold is paid at the order, and a cancel gives back `CANCEL_REFUND` of it. The `construction` system in `src/sim/systems/construction.ts` runs after `economy`, counts each city's work down a day while it is calm and not `beleaguered`, and emits `buildingFinished`.
- `buildingGain(state, city, kind)` in `src/sim/buildings/gains.ts` plays the city with and without a building through `dailyBalances`, `limitsOf`, and `fullDefences`, so a panel never restates a building's number.
- A city that falls keeps its finished buildings for the new owner, and `changeCityOwner` drops the one at work with a `buildingsLost` event. `sack` destroys every building with a `buildingsLost` event. `enslave` keeps them.
- The AI's rule is `construction` in `src/sim/ai/build.ts`: on a day it raised no recruit, with gold beyond its reserve and the price of the recruit it would raise next (`mostNeeded`), and food counted only while the harvest is tight (`FOOD_MARGIN_MEN`) and balances not falling, it starts the building that pays back soonest by `buildingWorth`, if within `BUILD_PAYBACK_YEARS`. Its constants sit at the top of that file.
- To add a building, add its kind to `BUILDING_KINDS`, its row to `BUILDINGS`, one function beside them that its hook reads, and its numbers to `buildingGain` if a new kind of number. Run `npm run sim:buildings` and put the tables in the pull request.
- The buildings raised `SAVE_FORMAT` to 11, after the 10 of the panels and saves unit.
- `npm run sim:buildings` prints the table, the years each building takes to pay back in a sample of cities with the first choice of each, and four Romes at peace for 5 and 10 years: one that does nothing, one that recruits, one that builds, and one that does both by the AI's rules.

### Sieges

- A city holds its `rank`, `walls`, `garrison`, and `foodDays`. `CITY_DEFENCES` in `src/sim/systems/sieges.ts` gives each rank's full values. `fullDefences(city)` scales its walls and food by `city.fortified`, and every rule that needs a city's full values reads it. A siege's damage stays on the city, and a city not under siege recovers a `1 / RECOVERY_DAYS` share of each full value a day.
- `sieges` runs after `battles`. An idle army with an unbroken formation within `SIEGE_DISTANCE` of a city whose owner it is at war with besieges it.
- A siege holds the blockade only while the besiegers' men are at least `BLOCKADE_ODDS` times the garrison. Below that, the food does not fall and the garrison sallies, killing `SALLY_SHARE` of its own number of besiegers a day, so a token force cannot starve a city. Later armies join the same siege. `siege.besiegers` is in order of arrival, and the first one's faction takes the city. An army leaves a siege by `moveArmy`, by being pulled into a battle, or when its owner is short of gold or food. `leaveSiege` and `removeArmy` in `src/sim/armies.ts` keep an army and its siege in agreement.
- Each day of a blockade the food falls by one day. With no food left, hunger takes `HUNGER_SHARE` of the full garrison. The walls lose `WALL_WEAR_PER_THOUSAND_MEN` for each thousand besiegers. The city falls when its garrison is gone or, once its walls are down, on a `GIVE_UP_CHANCE` roll, but never while an unbroken field army of its owner stands at it, and no storm is allowed then either.
- `storm` resolves at once in the order. It takes the city when the attack, with luck, is more than `STORM_ODDS` times the defence, which is the garrison raised by the walls. The stormers lose `STORM_KILL` of the defence in men either way, so storming intact walls costs a clearly stronger army a fifth to a third of its men and always fails for an army under 1.2 times the defence.
- `cityFalls` is the one way a siege takes a city. The winning besiegers leave `OCCUPATION_SHARE` of the city's full garrison from their own men as its new garrison, never more than half of them. It calls `changeCityOwner` and opens the fate with `city.fellOn`.
- `sack` and `enslave` are open for `FATE_DAYS` while an army of the owner stands at the city. Their shares sit in `SACK` and `ENSLAVE` in `src/sim/cities.ts`. Captives go to the faction's own capital from the map while it holds it, and to its most populous other city after it is lost. A sack sets `city.sackedOn`, and the city yields `SACK.poorOutput` of its gold for `SACK.poorDays` after it.
- Each fate is the best choice in its own situation. Occupy a city you mean to hold while your stores are sound: it out-earns a sack within a year and keeps the people who pay for it. Sack a city when gold is short now, to pay an army before it deserts or to recruit before an enemy arrives, or when you do not expect to hold it: the gold comes at once, and the city is poor for years. Enslave when manpower is short and gold is not, or to take people out of a city you may lose: a quarter of the captives become manpower at once, more than the occupied city raises in a year, and the rest move to your capital.
- `changeCityOwner` calls `defeatFaction(state, faction)` in `src/sim/defeat.ts` when the old owner holds no city left. It removes the faction's armies, convoys, and refugee columns, empties its stores, ends its wars, and sets `defeatedOn`. The record stays. Orders from a defeated faction, and wars declared on it, are refused.
- `npm run sim:sieges` plays the cases in `scripts/sim-sieges.ts` through `tick` and prints the tuning table.

### The clock and the panels

`src/app/clock.ts` turns real time into ticks and queues orders until the next tick. Panels never read the clock or the live state. They read `view.current` from `src/app/view.svelte.ts`, a `$state.raw` snapshot that is published about ten times a second. A click in a panel becomes an order through the clock.

### Faction AI

- `decideOrders(state, world, faction): Order[]` in `src/sim/ai/decide.ts` gives the orders one faction gives today. It takes a `DeepReadonly<GameState>`, never writes it, and draws no random numbers. Ties go to the lower id, so the same state gives the same orders. `decideAll(state, world, skip = [state.player])` gives the orders of every other faction that is not defeated, in faction id order.
- The clock calls it. `createClock` takes `decide(state)`, and each tick plays the player's queued orders and then `decide(state)` on the day being played. `src/app/main.ts` passes `(state) => decideAll(state, world)`.
- Every threshold is a named constant in `src/sim/ai/thresholds.ts`. Budget: `RESERVE_DAYS`, `MIN_BALANCE_SHARE`, `TROOP_MIX`. War: `WAR_ODDS`, `PEACE_WAR_ODDS`, `RIVAL_ODDS`, `RIVAL_PRESSURE_ODDS`, `WAR_DISTANCE_KM`, `WAR_REACH_KM`, `WAR_FRONT_KM`. Offence: `GARRISON_ODDS`, `ATTACK_ODDS`, `DEFENDER_KM`, `SEA_KM_FACTOR`, `STORM_MIN_CHANCE`, `STORM_MAX_LOSS`, `MARCH_MORALE`, `RALLY_WAIT_DAYS`. Defence: `RETREAT_ODDS`, `RELIEF_ODDS`, `RELIEF_KM`, `CAPITAL_GUARD_KM`. Fates: `ENSLAVE_BELOW_MANPOWER`. Minors: `MINOR_DEFICIT_DAYS`. The doc comment on each rule's function in `src/sim/ai` states the rule.
- A great power's day runs in this order: stances, retreats, fates, storms, army movements (capital guard, relief, offence), one recruit or else at most one building, at most one declaration of war. A minor gives orders only at war. Every faction sets the stance of each army in a battle to the one with the best `stanceEdge` over the stances of the enemy's men (`stances` in `src/sim/ai/stance.ts`): freely once in the battle, after that only while the enemy's stances beat its own and no enemy is re-forming, and never while it re-forms itself. It recruits its cheapest troop, keeps its armies at its city once their morale is back to `MARCH_MORALE`, and retreats from a battle it is losing. A minor starts with stores for its cheapest troop and a year of that troop's upkeep (`STARTING_STORES` in `new-game.ts`), so at war it fields a formation that meets the first besieger.
- A power weighs a neighbour by that neighbour's armies on land within `WAR_FRONT_KM` of its nearest city plus that city's garrison, so a rival whose armies are away invites war. It holds back all of an enemy's armies for each war it fights, but not its garrisons, which never leave their walls. Against the leader, a great power with `LEADER_SHARE` of all cities and more than any other, it needs no more than `COALITION_ODDS`. Against a rival great power it needs no more than `RIVAL_ODDS`. A power at war with no great power also presses a great-power neighbour that has kept to its homeland once its armies outweigh that neighbour's `RIVAL_PRESSURE_ODDS` times, so a player who stays at home is threatened. Every march the AI orders, the guard of the capital, a relief, and the way back to the muster city included, goes through the router, which prices no march longer than `MAX_MARCH_DAYS` and sails where the land is too far. An army sets out for a city only with `GARRISON_ODDS` times its garrison, counting the armies sent there with it, and only when the men there by the time it arrives, those besieging and those sent there whose road and sea are no longer than its own, hold the blockade. Armies already marching on a target together keep their course only when the first of them to arrive holds the blockade. It leaves for the muster city a siege that cannot hold the blockade, unless armies marching there, and given no other order that day, bring it up to the blockade before the sallies cut down half its men, and those armies keep their march. With no way to the muster city, it steps out of the siege onto land `STEP_OUT_KM` from the city. The muster city is never a besieged one.
- An army that no road and no port of its own takes to its muster city, such as one beaten overseas, sails from the shore it stands on, or marches to the nearest shore first (`wayFromShore` in `src/sim/ai/armies.ts`), and at peace the AI brings home an army that stands on land with no city of its owner. Every crossing the AI orders carries the march on to its target.
- No order joins two armies. A recruit joins the idle army at its city, so a power gathers by keeping an army at the muster city while recruits train, and sends separate armies at one target so they besiege and fight together.
- The AI caches each collection's sorted order, each faction's enemies, each army's strength, and the day's balances in `WeakMap`s keyed by the record objects. Never change a state's collections after the AI has read it.
- `npm run sim:ai [-- --seeds 20 --years 5]` plays the new game with every faction under the AI, then with Rome giving no orders, and prints the tables the thresholds were tuned on. Both `sim:ai` and `sim:world` print, from `scripts/standoffs.ts`, the armies that stand idle beside an enemy for more than 30 days and the armies idle overseas for as long, with those the menu gives no way home. `scripts/sim-ai-conquest.ts` adds the conquest and economy section by year and the five targets for a world that lasts, each marked met or not.
- `npm run sim:opening [-- --power <id>]` plays the scripted opening of each great power on 5 seeds: war on the nearest minor city on day 1 with the starting army, and the battles, siege, and fall that follow.
- `npm run sim:world [-- --from 1 --seeds 20 --years 10]` plays the new game under the AI and prints, for each seed, the cities of each power, who is largest, who is alive, the sieges begun again after the power ordered its besiegers away, the armies lost to sallies, the longest stretch a power at war sat still with an army that could fight, and the first city each power took. `npm run sim:recruit` has Rome raise every troop it can afford for two years and counts the days it waits on gold and on manpower.

### Renderer

- `createRenderer({ canvas, map, onPick })` in `src/render/renderer.ts` is the boundary. `src/app/main.ts` calls `draw({ previous, current, progress, selection, planned, previousSight, sight })` once per animation frame, and the renderer calls `onPick` with what a click points at. It reads the state and never writes it.
- `provinceAt(map, point)` in `src/render/pick.ts` finds the province under a map point, or nothing at sea. `pickAt` checks drawn figures and ships first, then army banners, and then calls it. Both are pure, so tests and any later rule use the same function.
- `src/render/camera.ts` holds the pan and zoom maths with no PixiJS import. `drawnArmies` in `src/render/markers.ts` places each banner between the previous and the current day by the clock's progress.
- The map is drawn as named layers, in this order from the bottom: `paper`, `sea` (fill, water lines, and the moving swell), `terrain` (the land's paper, desert ground, the green strips of desert rivers and the Nile delta clipped to land, wood ground, then the owners' washes, then fields, the regional texture, and three tiers of mountains, hills, trees, dunes, and stipple), `borders`, `riversAndCoast` (lakes with their own water lines, cached in a texture with the terrain, then rivers and the coast), `fog` (the shade and hatching over what the player cannot see), `grain` (the paper texture, printed over the drawing), `settlements` (`towns` with the town and village symbols, then `cities`, then `life` with smoke and boats, then `armies`, the figures), `markers`, `selection`, `labels` (city, peak, town, and village names, over everything so nothing covers a name). `LAYERS` in `renderer.ts` is that list. Add to a layer and keep the order.
- The terrain and the places live in `src/render/terrain/`. `marks.ts` places every drawing as plain data in km, a `Mark`, from the map's terrain areas, peaks, rivers, and settlements. `Land` holds the map's areas as rasters (`area-index.ts`): 4 km cells answer "inside?" fast, and a chamfer distance on 8 km cells answers "how deep?" and "how far from the edge?". `draw.ts` turns marks into PixiJS drawings, `terrain-layer.ts` builds them chunk by chunk, `places-layer.ts` places towns, villages, and names, and `life.ts` draws the smoke and boats.
- A drawing is seeded from its position. `scatter` in `scatter.ts` gives each cell of a fine lattice one candidate at a hashed spot with a hashed priority, and keeps it when no candidate of higher priority stands within their spacing. That rule reads only nearby cells, so the same map always draws the same way and chunks drawn apart meet with no seam. Each mark's own details come from `stream(seed)` in `random.ts`. Nothing in the renderer calls `Math.random`.
- The terrain is drawn into a texture 256 px larger than the view on each side and shown as one sprite, like the sea, so an idle frame costs one sprite. A cached texture of a new size is a new texture (`fitTexture` in `src/render/cached-texture.ts`), because Pixi's `RenderTexture.resize` leaves a texture that has been drawn into at its old size, and the sea, the terrain, and the fog then drew scaled and offset after a window resize. It draws again when the zoom changes, the texture no longer covers the view (`coversView`), or a chunk or tier fades. A resize that leaves the old texture covering the view keeps it until then, so the frame after a resize costs no more than another: redrawing the terrain and the sea at the new size in that one frame held the screen on the old frame for seconds on a software GPU. The canvas says the size of the last frame the GPU has finished in `data-drawn-size`, and counts those frames in `data-drawn-frames`. It says the zoom of the last frame drawn in `data-zoom`, so `e2e/wheel.spec.ts` can show that every wheel notch reaches the camera, however many arrive between two drawn frames. `resizeTo(page, size)` in `e2e/support.ts` resizes and waits for that, and the capture's clip takes no screenshot while a scenario resizes, because a screenshot in hand put the old size back. The wide tier is built when the renderer starts. Each other tier is cut into square chunks (`TIERS` in `marks.ts`). A chunk is placed and drawn the first time it comes into view, in slices of 12 ms on a timer between frames, so building runs at the speed of the main thread however slow the frames are. It fades in over 260 ms and is kept. The canvas carries `data-terrain="busy"` while chunks are missing or fading and `"ready"` after, which the capture waits for. Chunks out of view are hidden. Once the camera rests for 250 ms, the chunks around the view and those of the next finer tier are built ahead.
- `DETAIL` in `src/render/terrain/detail.ts` is the zoom rule, in px per km: the widest zoom of a 1280 px view is about 0.17 and the closest is 4. Desert and wood ground and lakes show at every zoom. Wide relief (ranges as ranges) shows to 0.66 and is gone by 0.92. Small tree marks in the woods and dunes and stipple in the deserts fade in from 0.26 to 0.4 and hand over to the middle tier with the wide relief. Middle relief with trees, dunes, stipple, and the named peaks fades in from 0.66 to 0.92 and out from 1.75 to 2.4. Close relief with hatched shading, and the open ground's tufts, scrub, rocks, and streams, fades in from 1.75 to 2.4. Towns fade in from 0.75 to 1.05 and their names from 1.5 to 2. Villages fade in from 1.7 to 2.3 and their names from 2.7 to 3.3. Peak names fade in from 1.4 to 1.9. Fields, orchards, and tracks, and the smoke and boats, fade in from 2.2 to 3. A symbol or name that gains its place fades in over 220 ms, and one that loses it hides at once, so names never overlap.
- Mountains stand along ridges that run parallel to a range's outline, larger and denser deeper in the range and near a high peak, and leave a valley along each river. Forest trees stand in woods, clumps of overlapping round patches that are denser deeper in the forest. Woods whose ecoregion name is Mediterranean get cypresses, conifer woods get pointed trees, and the rest get round crowns. Sand seas get more dunes than stony deserts. Fields ring every place out to `FIELD_RING`, and trees keep off the inner `FARMED_SHARE` of that ring. Open land outside the wood lobes, the fields, and the watered valleys shows its ground with the close relief (`ground` in `marks.ts`, drawn in one pass by colour under the relief, so it adds no chunk where the land had none): clumps of tufts and scrub, rocks near hills and mountains and on dry land, and here and there a stream.
- A city always wins a place over a town, and a town over a village (`claimSymbols` in `places.ts`). Names go through `placeLabels` with `LABEL_PRIORITY`: a great power's capital, any city, a peak, a town, a village. A name tries eight spots round its symbol and keeps clear of the symbols, the banners of armies that stand still, and the battle markers. A great power's capital is always named: with no free spot it takes the first one that clears the names already placed. A spot whose name crosses open water (`FAR_SHORE_PX`) onto another shore is not near its place and is never taken, so a long name at a wide zoom is not written over another coast, and a name with no other spot is not drawn at that zoom. A capital's name takes a spot written on land before one over the sea.
- Smoke and boats run on `performance.now()`, not on the game clock, and draw only while the life band shows and only where the player sees, so a boat in the fog never passes for a hidden convoy.
- City symbols are drawn in code in `src/render/symbols.ts`, one per `city.rank`: a great power's capital, its other cities, and a minor city. They grow up to 2.5 times at the closest zoom, and the town and village symbols grow by the same factor (`symbolGrowth` in `src/render/camera.ts`), so a city stays larger than a town and a town than a village.
- The selection lives in `src/app/main.ts` and reaches panels as `view.current.selection`. It is not game state.
- Dropping a save file on the page loads it through `loadGame` and `clock.load`.

### Panels

- `src/ui/Hud.svelte` is the one root the page mounts. It lays out one grid over the map: the top bar, the overview under it, and the alerts at the bottom left, with the side column of the army, city, and battle panels at the right edge under the top bar, which spans the width. From 1024 px the top bar keeps one row: each store and the clock stand as two short lines, a store's note is a word or two, and its full reason is the store's tooltip (`storeNote`). The `?frames` readout sits at the bottom right. Below 720 px the side column becomes a sheet at the bottom, and while it holds a panel the corner alerts give way to it, but the Chronicle button above them stays. The side column scrolls inside itself. The grid lets clicks through to the map, and only the panels take them. The clock, the stores, and the speed buttons are never covered. The refusal notice and the right-click menu float above it. Panels read `view.current` and act only through `Actions` in `src/ui/actions.ts`, which issue orders to the clock, select, and move the camera.
- A panel prop that holds the game state is named `game`, because Svelte reads `$state` next to a local named `state` as a store.
- A right click reaches `onCommand` in `src/app/main.ts`. The renderer names the city whose symbol or label the click is on or within 10 px of, as `Command.city`, and a symbol wins over a label. `planCommand` in `src/app/command.ts` then decides what the click does with the selected army: march to the city or the point, or, when the army stands at one of its ports and the click is on another port, a menu of the ways by sea and by land that the rules allow, with their days. It plays each order on a copy of the state through `executeOrder`, so what it offers and refuses is the rules' answer, and it refuses at once in words what the rules would refuse. The ways it weighs are the march and the quickest way by sea (a march of at most `MAX_MARCH_DAYS` to a port of the army's owner or to the nearest shore, the days that gather ships on a shore, the crossing, and the march on from the landing, which the embark order carries as `then`), and it drops a way that takes more than `FAR_LONGER` (1.5) times the days of the quickest. A click whose march is dropped opens the menu with the way by sea, and a click with no way left is refused with the reason.
- The army panel names the city of its owner a retreat ends at, as "Retreating to Roma", and says "Falling back into the field" for a retreat that ends at none, so it never names the enemy city the army fled from (`activityText` in `src/ui/describe.ts`).
- An army the panels call "at" a city stands within `AT_CITY_KM` in `src/app/names.ts`, which is `SIEGE_DISTANCE`, so an army at an enemy city at war besieges it. The army panel says why an idle army at a foreign city does not besiege it, and an idle army within `ENGAGEMENT_DISTANCE` of an enemy city but too far to besiege it says so and offers Besiege, the march to the city (`whyNotBesieging` in `src/ui/describe.ts`).
- The clock keeps one waiting order per army and slot: a movement slot (`moveArmy`, `halt`, `embark`, `retreat`) and a stance slot. A new order replaces the one in its slot. Orders that name no army wait side by side. The top bar counts the armies with an order waiting.
- The battle panel shows the stance buttons and the retreat for each of the player's armies in the battle, through `StanceControls.svelte`, which the army panel shares. An army in battle shows them only in the battle panel, which always stands under it, so they show once. Each stance's line comes from `STANCE_EFFECTS`. Beside each stance it says what the stance beats and what beats it (`stanceMatchShort`, from `STANCE_BEATS`), each other stance's button says what a change costs (`stanceChoiceText`, from `REFORM_DAYS`), and an army that re-forms says how many days are left (`reformingText`). In a battle one line says whose stance beats whose (`standingText`, by the battle's own `edgeBetween`), and the button of the stance that beats the enemy's is marked. The battle panel's rows give each army's stance and whether it re-forms, and the guide lists the stances from the same functions. The army and city panels list the other armies in sight at the same place.
- The Game menu's Start screen asks first, with the game paused (`askToLeave`, the `leave` modal): save and leave, which writes the `manual` slot, leave without saving, or stay, which runs a game that was running. A player who has lost goes straight to the start screen.
- `src/ui/WarsPanel.svelte` is the one place for peace: each of the player's wars and how it stands (`warRoomOf` in `src/ui/war-room.ts`), the enemy's offer with Accept and Refuse, terms ready to offer and terms to write, each with the enemy's answer from `peaceAnswer` and its reasons, and the truces with their days left. It is the `wars` panel of `panel` in `main.ts`, and the overview's wars open it. An AI's offer to the player is a `peaceOffer` turning point that pauses the game and opens the panel on that war. The city panel's `WarStatus` says how long a truce holds in place of the button that declares war.
- The top bar's Overview and Chronicle open one panel at a time over the map's left side, which is page state (`panel` in `main.ts`). The Overview is a list of the player's cities, armies, and wars (`overviewOf` in `src/ui/describe.ts`). A click on a row calls `actions.show`, which selects and centres the map. A city's rank line comes from `rankText`, which reads the starting owner from the map. Once the player is defeated, `overviewOf` gives only the day the realm fell, and the panel lists nothing.
- The renderer also takes `onCommand` for a right click and offers `focus(point, covered)` for an alert's click, which centres the point in the part of the map that the screen insets `covered` leave clear. `main.ts` measures the top bar, the overview, and the side column for it each time, so what was chosen never lands under a panel. A left click that finds a province or nothing also takes the city whose symbol or name it is on or within `CITY_HIT_MARGIN` of (`cityAt`), so a click on a name selects that city. A click on a city's symbol itself picks the city before the figures round it. A camp's tents and stacks of arms answer to their army like its men, so a click on them selects the army, not the province under them. In the `markers` layer it draws the player's march and sea paths, the paths of orders still waiting, and a battle marker that `pickAt` selects after banners and before provinces. An army at sea is drawn at its convoy.
- `alertsOfDay(before, after, events)` in `src/app/alerts.ts` works out the alerts of a day, and the clock's `onDay` feeds it every tick with the tick's events. News of something that happened, such as a battle, a retreat, a lost army, desertion, or a declaration of war, comes from the events, so a battle that begins and ends inside one tick is still told. Only standing changes, such as a city's owner, a new siege, a mustered formation, an arrival, or an empty store, are read by comparing the two days. Alerts are page state, not game state. To add a kind, add it to `ALERT_KINDS` and one test to `alerts.test.ts`.
- An offer of peace, a refusal, and a peace are alerts from the events `peaceOffered`, `peaceRefused`, and `peaceMade`. A peace between two other great powers is told too.
- The page keeps every alert of the game, newest first, up to `CHRONICLE_KEPT` in `src/app/page.ts`, as the chronicle. The corner list shows the latest five and the Chronicle panel all of them.
- An alert carries `pause` when its news may stop the game: a battle of the player begins (`battle`), a siege of the player is too weak to starve the city (`weakSiege`, the test of `weakSiegeNews`), and an enemy first nears the player's land in a war (`sighted`, once per war by `pause.once`). `stopsOfDay` in `src/app/pauses.ts` marks the alerts that stop the game `paused`, by the Game menu's settings, which local storage keeps across games, all on by default. `onDay` then pauses the clock, which runs no further day of the frame, so the game stops on the day of the news. The camera stays where it is, and the alert says "Paused". `?pauses=off` keeps the news from stopping the game.
- An alert is dated by the day played, the day the rules stamp on what happened in it (`fellOn`, `defeatedOn`, a war's `since`), and the list writes it with `dateText`, as the screens do.
- `sightingsOfDay` tells of a convoy or a marching army of a power at war with the player that comes into sight on its way to the player's land (within `THREAT_KM` of a city of the player, or on its provinces), with its men and the city it heads for when the player sees that place. `weakSiegeNews` tells on the day a siege of the player's is too weak to cut the food, and again once its besiegers have lost `BLED_SHARE` of their men in it, to sallies or a storm, which the page cannot tell apart; the page keeps what it told in `weakSieges`. `alertsOfDay` tells when an evacuation leaves and when its people settle, and the overview lists the columns on the road.
- `worldNewsOfDay(before, after, events)` in `src/app/world-news.ts` gives the news of the world that every power hears, in sight or not: a war between two other great powers and their peace, a great capital that falls, a great power destroyed, a new leading power (`leadingPower`, the AI's rule of `LEADER_SHARE`), and a city within `NEAR_KM` of the player's that changes hands between two others. It never tells of the player, whose own news `alertsOfDay` gives, and it pauses nothing. An alert's `world` says how far it reaches: `corner` news shows in the corner list, drawn quieter than the player's own, and `chronicle` news, the cities near the player's land, only in the chronicle (`cornerAlerts`). `npm run sim:news` counts the lines a year that the corner and the chronicle get, with Rome idle and under the AI.
- `sightingsOfDay` tells fleets of one power seen on one day sailing for one place as one line with their men together, and marching armies the same.
- `groupAlerts` folds the alerts of one kind with the same text at one place on one day into one line with a count. The page runs it after `alertsInSight`. A besieged city that musters its recruits early (`earlyMusters`) is one `musteredEarly` alert, to its owner and to the player besieging it, in place of the muster line of each formation it mustered early. A recruit that was due that day anyway keeps its own line.
- An alert covers the player's own armies and wars, and the battles, lost armies, and desertion of others that the player sees. The end of a battle gives its days and each side's losses. Desertion is told on the first day the owner is short. `alertsInSight` drops the rest. An alert selects a battle or an army only while it still exists.
- The city panel gives an own city's gold and harvest from `cityBalance` in `src/ui/describe.ts`, which runs `dailyBalances` on a realm of that city alone and cuts its gold and manpower by `adminShareOf` for the owner's realm, so it restates no rate and the cities of a realm add up to its balance. Its walls and food are out of `fullDefences(city)`. For a minor's city it says in plain words what a war with it meets (`minorText`): rich and walled or poor and open, its league partner, and its army at the city while the player sees it. `stormText` gives the storm confirmation the chance to take the city and the men it is expected to cost, from `stormOdds` in `src/sim/ai/situation.ts`. `sackText`, `storeNote` (a store at its `limitsOf` limit, or the days a falling store lasts), and `weakSiegeText` (besiegers fewer than `BLOCKADE_ODDS` times the garrison, with the men still needed) are the other lines, each with its unit test. `weakSiegeText` says nothing while a besieger is out of sight.
- A fate chosen in the prompt is an order, so it waits for the next day. Closing the prompt runs a game that the fate stopped, but a game paused by other news of the day, or by the player, stays paused. The page then says when the fate happens, and the city panel shows the fate ordered in place of its choices.
- `reasonText` in `src/app/names.ts` turns a rule's refusal into words a player reads. The notice shows it for four seconds.
- The view times each refresh as the user-timing measure `panels`. The `panels` capture scenario reads it.
- `e2e/support.ts` builds saves for browser tests and capture scenarios, such as a battle or a fallen city. Tests drop them on the page and then play through the panels.

### Fog of war

- `sightOf(state, world, faction)` in `src/sim/sight.ts` says what a faction sees: the `armies`, `convoys`, `refugeeColumns`, and `battles` in sight, and `sees(point)`. A faction sees the land of its own provinces and within `SIGHT_KM` of its cities, its armies on land, and its convoys. It always sees its own things. A battle with any part in sight is seen with every army in it. The map, the cities, and their owners are always known.
- Sight is only what the player is shown. The rules and the AI never call it.
- A defeated player who watches on sees the whole map: `sightFor` in `src/app/main.ts` gives `sightOfAll` from `src/app/sighted.ts` once the player's `defeatedOn` is set. The top bar then says the realm has fallen in place of the stores, and the defeat's emptying of the stores raises no `storeRanOut` alert.
- `src/app/main.ts` computes the player's sight once per day's state and hands it to the renderer as `sight` and `previousSight`, and to panels as `view.current.sight`. The renderer draws and picks only armies and battles in sight. `seesPick` and `alertsInSight` in `src/app/sighted.ts` keep the selection, a panel's selection, and the alerts to what the player sees, so a selection that leaves sight is cleared and a click on an alert selects nothing hidden. A new panel or alert shows nothing outside `view.current.sight`.
- A wash is an owner's colour laid at `WASH_STRENGTH` (`src/render/palette.ts`) over the ground in the terrain's cached texture: the paper, the desert, and the wood, under the relief, trees, and fields, so every drawing keeps its ink and its lit and shaded sides. It is laid on with a normal blend, not multiplied, so a colour keeps its hue on the yellow desert, where a multiply turned Carthage's violet into Rome's red and Macedon's blue grey. A change of owner calls `terrain.repaint()`.
- `src/render/fog.ts` draws the `fog` layer. The fog lifts once the player is defeated, who then sees the whole map. Its mask is drawn in km into a texture, so a pan only moves it. The land part is blurred when ownership changes, and each sight circle is a soft disc placed between the two days by the clock's progress.

### The frame round the game

- The page opens on the start screen with the clock paused. Choosing a power runs `newGame` as that power, paused, with the camera on its capital and the guide open. "Continue" loads the save written last. `?play=<power>` skips the start screen and the guide and opens a running game at the widest zoom.
- `outcomeOf(state, world, faction)` in `src/sim/outcome.ts` says whether a faction plays on, has won, or has lost. `VICTORY` holds the numbers: 40% of all provinces and 3 great capitals, its own among them. `standingOf` says how far the faction stands from them. The rule is a pure function of the state, and nothing in the rules acts on it.
- `turningPoints(before, after, world)` in `src/app/turning-points.ts` finds the days the page stops for: the loss, the win, and a city the player took whose fate is open. The clock's `onDay` feeds it. The page queues them as modals in `src/app/modals.ts`, one in front at a time, and stops the clock after the frame's days. Closing the last modal runs a game that a modal stopped. The win is announced once a game.
- `fateChoices` in `src/app/fates.ts` plays the sack and enslave orders on a copy of the day, so the fate prompt shows the rules' own numbers. For each fate it gives what it gains now, the days of unrest, what the city yields a day at first (`unrest`), and what it yields once calm (`calm`, `cityBalance` of the city on the day its unrest ends), one line each. The days of unrest are `unrestDaysLeft`, the counter divided by the pace the rules count it down at (`unrestPaceOf`, faster near the owner's temple), and the prompt and the city panel write them with the same `unrestText`. A panel never restates a rule's number.
- The rules have no order to occupy. A choice of Occupy, in the prompt or the city panel, is page state: `occupied` in `src/app/main.ts` maps the city to the day it fell, which closes its fate at once and keeps `alertsOfDay` from telling that the days to choose ran out.
- A save holds the page beside the state (`saveGame(state, page)`): the chronicle, the camera, the selection, the open panel, the cities the player chose to occupy, and what the news has told (the spent `pause.once` keys and the watched weak sieges), so a loaded game neither tells it again nor stops twice. `parsePage` in `src/app/page.ts` checks it, and loading puts the player back where they were, with the camera through the renderer's `camera()` and `lookAt`. A save with no page, such as one a test writes, opens with the camera on the player's land as before.
- `src/app/saves.ts` keeps two browser slots, `manual` and `auto`. The game writes `auto` on the first day of each 30-day month after the first, and never for a player who has lost. Each slot holds the text of `saveGame`, so loading one runs every check of `loadGame`, and a refused save shows the same notice as a dropped file.
- `src/ui/frame-actions.ts` is what the start screen, the guide, the defeat and victory screens, the fate prompt, and the Game menu may do. `GAME_NAME` there is a working title.

### Armies on the map

- The figures are SVG art built in code in `src/render/figures/`: `human.ts` is a man on foot, `horse.ts` a horse, and `things.ts` the ship, tents, fires, smoke, dust, arrows, javelins, ladders, stakes, the ox cart, and the standard. Each body part, shield, weapon, and horse part is a shape on a joint. `motions.ts` poses every kind in `KINDS`, the six troops of `TROOPS`, the general, the standard bearer, and two refugees, for each motion in `MOTIONS`: `stand`, `march`, `fight`, `run`, and `fall`. Walking, running, and the horse's walk and gallop are cycles over the joints, so they loop exactly. The weapon actions (thrust, cut, throw, loose, charge, lead) and the fall are keyframes. A paint list fills shapes with fixed colours or with a shade of the owner's colour, so one list paints every faction.
- `sheet.ts` packs every frame of every picture into a sheet, one copy per colour in `SHEET_COLOURS` (the five powers and the minors' grey). `src/render/armies/layer.ts` rasterises one sheet per size in `SHEET_SIZES` (14 to 120 device px per man's height) and per colour, lazily, once the zoom rests at a size and a sprite in view needs that colour, and draws each figure as a sprite of the smallest sheet at least as large as it is on screen. A figure is never enlarged and is shrunk by at most a third. The `figures` capture scenario shows the plate.
- `buildScene` in `src/render/armies/scene.ts` is a pure function from the two days, the clock's progress, the camera, the sight of both days, and two clocks to the sprites, wakes, siege works, and wall breaches of the frame. The renderer only copies it into PixiJS. It draws only the armies, convoys, and columns in `sight`, and a click picks only what it drew. Its unit tests start from `buildFixture()`.
- The figures draw in the `settlements` layer above the city symbols, so city names stay readable over them. A battle that would cover a city is drawn just clear of it, and its marker follows.
- Below `FIGURE_SCALE` (0.9 px per km) an army is its flag, as before. From it, a man stands 13 px tall, growing to 54 px at the closest zoom, and the flags give way to figures. A battle's marker then stands above its fighting.
- `figuresFor(men)` in `armies/count.ts` gives each formation one figure per `MEN_PER_FIGURE` (50) men, rounded up, to at most `FIGURE_CAP` (30). The army adds its standard bearer, and its general when `generalSkill` is above 0. A convoy shows one ship per 400 men, up to six, and a refugee column one walker per 1,000 people, 3 to 12, with an ox cart in every five.
- A block stands four files deep for foot, three for archers, skirmishers, and horse, and as many ranks long as its figures need, each figure a seeded step off its mark. At rest the blocks stand in two lanes behind the standard and the general. Beside a city they face it from its landward side and stand clear of its symbol and its name, on the side away from the name when there is land there. On the road they march in column along the path walked that day. An army at rest and a battle's lines stand on land: `landShift` in `armies/scene.ts` moves them by the smallest step that brings the ground every figure covers onto land, as `Land` answers through the scene's `land` input, and leaves an army inland where it is. A figure covers its feet or a horse's hooves to either side, `groundSpan` in `figures/sheet.ts`, read from its art. A figure the layout of its army still leaves off land, such as a man running from a broken line or one of a column on a road the rules lay over a lake, steps to the nearest dry place within a man's height or two (`nudge`), or is not drawn. `armies/every-city.test.ts` puts an army at rest, on the march, in a battle, and in a siege camp at every one of the 80 cities of the map at four zooms, fails when a case cannot be set up or draws nothing, and finds no figure, tent, fire, or stake on water. The same file checks that a siege camp at Mediolanum and at every coastal city leaves the towns near it, their names, and the city's name clear. In battle each side forms a line at the battle's place, the two lines facing each other across it, with the foot in the centre, the horse on the wings, and the archers and skirmishers behind. A besieging army takes its share of a ring round the city's landward side, with tents, fires, stakes, and a ditch. The ring keeps to the angles where every row of it stands on land and clear of the town and village symbols and names drawn near the city and of the city's own name (`keepClear`, which the renderer gives the scene), so the places round a siege stay readable. Where a coast leaves too little of the ring clear, it keeps to the land, and a besieger, tent, fire, stake, or stack of arms that would still cover a place steps clear or is not drawn.
- `formationDay` in `armies/losses.ts` turns a formation's two days into its falls and its rout. The figures the day loses fall among the front ranks early in the day and fade at its end, while the figures at the back step into their places. A formation whose morale reaches 0 turns and runs at a seeded time, and stands broken behind the line while its army fights on.
- The scene reads facts and draws nothing the rules do not hold. A camp is pitched when an army stood idle at the same place on both days. A storm shows on the day a siege's armies lost heavily and stayed at the siege or took the city (`stormedBy`): the ring stands back from the wall, two dark ladders lean against the front wall with a man fighting at each head and one climbing, and a volley of arrows flies over the walls from the ring's landward side, all drawn over the ranks. A sacked city burns and smokes for `BURN_DAYS` (6) from `City.sackedOn`, dying down over the last two. The new owner's flag stands over a fallen city until its fate is chosen.
- Marching, fighting, rowing, and the flight of arrows follow the motion clock in `renderer.ts`. It runs with the game's days, faster at a higher speed, and stops while the game is paused. Men at ease, fires, smoke, dust, flags, and the bob of ships follow real time, so a paused map is still alive. The figures of a formation are out of step by a seeded phase and rate.
- `e2e/support.ts` builds the saves the capture scenarios `zooms`, `march`, `battle`, `siege`, `crossing`, `column`, and `speed` start from. `speed` prints the frame cost.

## Code and tests

- TypeScript strict. No `any`.
- Write a comment only for a reason the code cannot show.
- Tests assert behaviour that a player or a caller can observe, not internals.

A browser test or a capture scenario enters a game through `openGame(page, { query, power, pauses })` in `e2e/support.ts`, which opens `/?play=rome` and waits for the top bar. It adds `pauses=off` unless `pauses` is true, so a test that plays through a battle at speed sees it play out, and a test of the pauses says that it wants them. Only a test of the start screen opens `/` itself. Browser tests draw the test drawing, because a browser test checks behaviour and not the picture, and CI draws in software. `playwright.config.ts` stores `draw=test` in the page's local storage, and `?draw=test` does the same by hand. `TEST_DRAWING` in `src/render/draw-options.ts` lists what it leaves out: the paper grain, the moving swell, and antialiasing, and it draws at half resolution, so a page draws only when something changes and a frame costs a fifth of the full one in software. A page opened with `?draw=full` draws everything, as the game and `npm run capture` do, and the smoke test does so. A browser test waits for the state it needs, such as a day, a panel, or a text, and never for a fixed time or a count of days in a count of seconds. To know the day by which something happens, play the state forward with the rules in the test, as `firstDayWhen` in `e2e/fog-game.ts` does. `?frames` shows the frame interval and the time of each drawn frame, median and p95 over 5 s, and `node e2e/frame-bench.ts` prints that for each layer and switch (`hide=<layer>`, `swell=off`, `antialias=off`, `resolution=<n>`) after `npm run build`, at the zooms `--zooms widest,middle,closest` names, and for another checkout's build with `--root <dir>`. A frame starts only once the GPU has finished the one before: `draw` places a WebGL2 fence after each frame and draws nothing while it has not signalled, so a slow GPU never queues frames and a click or a screenshot waits one frame at most. A held frame sends the GPU nothing, not even a render into a texture, and keeps every change for the next frame. It only lays the cities out again, which is CPU work, so a click picks what the screen will show (`FramePacer` in `src/render/frame-pacer.ts`). `?frames` takes the `waitForGpu` path and places no fence, so the frame bench cannot show a skip. The capture's clip takes a frame only once the map has drawn, and skips a frame it cannot take in 5 s, because a screenshot asked for while a page loads can wait out its whole timeout and hold up the scenario's own shots behind it.

To show a new view, add a scenario file to `scripts/capture/scenarios/`. It default-exports `defineScenario({ name, title, run })`. `run` gets the Playwright `page` and `shot(name, title)`. The whole run becomes the clip.

CI runs `npm run capture` on every pull request and publishes the media to `pr-assets` under the branch name. The run summary holds the Markdown. If your machine cannot install Chromium, push the branch, wait for CI, and run `npm run capture:fetch`. CI keeps the full video, the trace, and the Playwright report as run artifacts.

## Git

- One branch per unit. Open a pull request to `main`. Never push to `main`. Squash merge only.
- Use Conventional Commit titles, such as `feat(sim): add movement system`.
- Add no `Co-Authored-By` trailers and no generated-by footers.
- Never commit captured media. `capture:publish` stores it on the `pr-assets` branch.
- Nexus runs `.nexus/check` (install, `npm run check`, `npm test`, `npm run build`) in a fresh pylon before it lands a pull request. A pull request that changes `.nexus/check` or `.nexus/setup` gets a hold that the owner must waive, so leave both files alone unless your brief says otherwise. Nexus runs `.nexus/resume` on every wake and after it checks out a commit on a template, where it reinstalls the packages when `package-lock.json` differs from the one last installed, and a pull request that changes it gets the same hold.

## Pull request description

Use these sections in this order: Why, What changed, Scope, Blast Radius, Verification.

- Verification lists each command you ran and its real outcome.
- A pull request that changes anything visible embeds the screenshots and at least one clip from `npm run capture`. It names its Nexus preview URL. `npm run capture` and `npm run capture:fetch` declare the media as Nexus outputs.
- A pull request that changes only rules shows the test output.

## Scope

Stay inside the paths the brief names. Note unrelated problems in the pull request and do not fix them there.
